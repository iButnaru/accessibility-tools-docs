# 🌎 Glossary

{% hint style="success" %}
Specific acronyms have been used to shorten the length of some sentences and make them more easily readable (for example, desc, info, or alt).
{% endhint %}

<table data-full-width="true"><thead><tr><th width="156.92327880859375">Term</th><th>Definition</th></tr></thead><tbody><tr><td>&#x3C;a> element (anchor element)</td><td>An HTML tag used to create hyperlinks. It allows users to navigate to other web pages, files, sections within a page, or other resources when they click or interact with it.</td></tr><tr><td>Alt text</td><td><p>A short text alternative with the alt attribute used on the &#x3C;img> element. The value of this attribute is referred to as "alt text". When an image contains words that are important to understanding the content, the alt text should include those words.</p><p>Different from aria-label because alt-text is used only on &#x3C;img> elements.</p></td></tr><tr><td>aria-label</td><td><p>An HTML attribute used to give accessible, descriptive labels to HTML elements that otherwise lack visible labels. Part of the ARIA (Accessible Rich Internet Applications) specification, aria-label helps assistive technologies like screen readers identify and convey the purpose of a particular element to users with disabilities.</p><p>For example, if an icon button has no visible text, adding aria-label="Submit Form" will let a screen reader announce "Submit Form" when it reaches the button, even though visually there is no text displayed.</p><p>Different from Alt-text because aria-label is used on any type of graphics, not the &#x3C;img> elements.</p></td></tr><tr><td>AT</td><td><p><strong>Assistive technologies</strong> (ATs) are hardware and software tools that help people with disabilities access and interact with digital content and user interfaces.</p><p>Common types of assistive technologies:</p><ul><li><strong>Screen readers</strong> - read text aloud and provide navigation for blind/low vision users</li><li><strong>Screen magnifiers</strong> - enlarge screen content for low vision users</li><li><strong>Voice recognition software</strong> - allows input through speech</li><li><strong>Alternative keyboards</strong> - specialized keyboards for motor impairments</li><li><strong>Switch devices</strong> - single-button controls for users with limited mobility</li><li><strong>Eye-tracking systems</strong> - control interfaces through eye movement</li><li><strong>Cognitive support tools</strong> - help with memory, attention, or processing</li></ul></td></tr><tr><td>ATAG</td><td>Authoring Tool Accessibility Guidelines, a set of standards to make the authoring tools themselves accessible (so that people with disabilities can create web content) and help authors create more accessible web content.</td></tr><tr><td>Captions</td><td><p>Text displayed on-screen in sync with audio during a video. Captions include spoken dialogue and relevant sounds (e.g., “door creaks” or “[music playing]”) to provide context for viewers who are deaf or hard of hearing. Captions appear in real time and are typically embedded in the video itself.</p><p>Disambiguation: Transcriptions provide a complete, static text document, while captions are synchronized text displayed within video content.</p></td></tr><tr><td>cc</td><td>Closed captions display text on-screen in real time with video content, representing spoken dialogue, sound effects, and other relevant audio cues. They are primarily designed for people who are deaf or hard of hearing and can be turned on or off by the user, unlike open captions, which are permanently visible.</td></tr><tr><td>Change of context</td><td><p>Major changes in the content of a web page that, if made without user awareness, can disorient users who cannot view the entire page simultaneously.<br>Examples: </p><ul><li>Opening a new window, tab, or pop-up</li><li>Moving focus to a different component or significantly changing content layout</li><li>Significantly altering the meaning of the web page</li><li>Automatically submitting a form when a dropdown selection is made</li><li>Opening a new window when a link is clicked without warning</li><li>Automatically redirecting to a new page</li><li>Dramatically changing page layout or navigation</li><li>Moving focus to a different part of the page unexpectedly</li></ul></td></tr><tr><td>Control</td><td>Elements that a user can click, tap, or interact with to carry out a specific action (e.g., buttons, navigation links, checkboxes, sliders; user uses them to submit a form, open a new page, toggle a setting).</td></tr><tr><td>CSV</td><td><p>Comma Separated Values. </p><p>In Accessibility Tools, this is the format in which test results are exported. For more information, see ???.</p></td></tr><tr><td>dir (rtl / ltr)</td><td>Text direction (right-to-left/left-to-right)</td></tr><tr><td>DOM</td><td>Document Object Mode, a programming interface that represents the structure and content of a web page as a tree of objects. It allows developers to dynamically access, modify, add, or delete elements and content within a webpage using scripting languages like JavaScript.</td></tr><tr><td>Down events</td><td><p>Pointer interactions that occur when a pointing device (like a mouse button, finger on touchscreen, or stylus) is initially pressed down or makes contact, before being released. </p><p>Examples: </p><ul><li>Pointerdown</li><li>Mousedown</li><li>Touchstart</li></ul></td></tr><tr><td>em unit</td><td>EM units are a relative measurement in web design and typography, where 1 em equals the font size of the parent element. They are commonly used for scalable and responsive font sizes, spacing, and layout design. For example, if the parent font size is 16px, 2em will be 32px. Unlike absolute units like pixels, em allows designs to adapt dynamically by scaling relative to their context.</td></tr><tr><td>Form controls</td><td><p>Interactive elements on web pages that allow users to input data, make selections, or trigger actions within forms, such as:</p><ul><li>Text input     </li><li>Checkboxes</li><li>Radio buttons</li><li>Combo boxes</li><li>List boxes</li><li>Buttons</li></ul></td></tr><tr><td>Glyphs</td><td>Visual representations, or shape of a character. For example, the Unicode characters U+0033 and U+04E0 both look like the number "3", yet the latter is actually a letter from the Cyrillic alphabet. <strong>α</strong> (Greek letter alpha), <strong>€</strong> (Euro currency symbol), <strong>♦</strong> (diamond suit symbol), <strong>∞</strong> (infinity symbol) and  <strong>©</strong> (copyright symbol) are all glyphs.</td></tr><tr><td>Info</td><td>Information</td></tr><tr><td>Input</td><td>Fields where users enter information (text fields - for names, emails, etc., radio buttons, date pickers, dropdown menus). Used for gathering info from users - when creating accounts, searching for products, entering payment details.</td></tr><tr><td>ltr</td><td>Text direction left-to-right (dir attribute)</td></tr><tr><td>Motion actuation</td><td><p>A functionality triggered by device motion or user gestures (tilting, shaking, or moving a device) to control UI elements or activate features.</p><p>Examples:</p><ul><li>Shaking a phone to undo text input</li><li>Tilting a device to steer in a game</li><li>Rotating a tablet to trigger screen orientation changes</li><li>Moving a device to control navigation or scrolling</li><li>Gesture-based controls using accelerometer/gyroscope data</li></ul></td></tr><tr><td>Non-text elements</td><td>Any content that is not a sequence of characters that can be programmatically determined or where the sequence is not expressing something in human language. Examples: Images (photographs, illustrations, icons, and graphics), charts and graphs, diagrams, time-based media (audio/video content) and so on.</td></tr><tr><td>Non-text content</td><td>Any not written/readable content which still conveys meaning/important information (images, audio and video, interactive media - charts, graphs, maps, infographics -, user interface components - buttons, sliders, other controls). This content requires text alternatives or other forms of accommodation.</td></tr><tr><td>OS</td><td>Operating system, system software that manages computer hardware and software resources, and provides common services for computer programs.</td></tr><tr><td>PD</td><td><p>Programmatically determined means that information can be read and processed by software, particularly assistive technologies, through properly structured code and markup rather than relying solely on visual presentation.<br>Examples:</p><ul><li><strong>Form label association</strong> - Using <code>&#x3C;label for="email"></code> connected to <code>&#x3C;input id="email"></code> allows screen readers to programmatically understand that "Email Address" is the label for the input field, rather than just visually positioning text near the field.</li><li><strong>Heading structure</strong> - Using proper heading elements <code>&#x3C;h1></code>, <code>&#x3C;h2></code>, <code>&#x3C;h3></code> creates a programmatically determined hierarchy that assistive technologies can navigate, unlike just making text visually larger with CSS styling.</li><li><strong>Table headers</strong> - Using <code>&#x3C;th></code> elements with <code>scope="col"</code> or <code>scope="row"</code> programmatically identifies which cells are headers and their relationships to data cells, enabling screen readers to announce "Sales, Quarter 1: $50,000" instead of just reading disconnected numbers.</li></ul></td></tr><tr><td>PDF</td><td><p>Portable Document Format, a file format for capturing and sending electronic documents in exactly the intended format. </p><p>In WCAG, some test cases target PDF files.</p></td></tr><tr><td>Programmatically determined</td><td>Information—such as the name, role, or state of a user interface component—can be identified and processed by assistive technologies through code. Thus, screen readers and other tools can access and convey the purpose and function of elements (like form fields, buttons, or links) to users who rely on these technologies. For example, if a button’s role (e.g., “submit”) and name (e.g., “Submit Form”) are set in the code, a screen reader can automatically read these aloud, making the interface accessible.</td></tr><tr><td>rtl</td><td>Text direction right-to-left (dir attribute)</td></tr><tr><td>SMIL (1.0, 2.0, 2.1)</td><td>Synchronized Multimedia Integration Language 1.0. SMIL 1.0 provides a structured way to ensure multimedia content is accessible, aligning with WCAG requirements for synchronized alternatives like captions, audio descriptions, or text alternatives for time-based media. It is particularly useful in scenarios involving complex multimedia presentations.</td></tr><tr><td>Sticky content</td><td><p>Webpage elements that remain fixed in their position on the screen as users scroll, staying visible even when other content moves past them.</p><p>Examples:</p><ul><li>Headers that stay at the top of the page while scrolling.</li><li>Navigation menus that remain accessible.</li><li>Footers that stick to the bottom of the viewport.</li><li>Sidebar elements that follow the user down the page.</li><li>Floating action buttons or chat widgets.</li></ul></td></tr><tr><td>SVG</td><td>Scalable Vector Graphics, a vector format used in logos, icons, and illustrations that need to scale without losing quality. SVG files are small and perfect for responsive web design.</td></tr><tr><td>Test</td><td><p>In Accessibility Tools, a test is a specific evaluation method that determines whether web content meets a particular WCAG success criterion via test cases. Each test consists of multiple test cases (see definition below). </p><p>In Accessibility Tools, WCAG tests are: </p><ul><li>Automated, using tools to check measurable criteria like contrast ratios </li><li>Manual, requiring human judgment for content quality </li></ul><p>Read more about how to work with tests in Accessibility Tools <a href="https://docs.google.com/document/d/1MG0kg7X6cMLZtGq_La4JmHOLdLkhqd3M34FtHkLg8hU/edit?tab=t.0#heading=h.s7gfaw2on2r8">here</a>.</p></td></tr><tr><td>Test cases</td><td><p>Test cases are predefined steps, conditions, and expected results that assess accessibility features such as keyboard navigation, screen reader compatibility, color contrast ratios, alternative text presence and so on. </p><p>Accessibility Tools include both automated and manual tests. Manual tests should be performed by qualified specialists.</p><p>Depending on their status, test cases may be:</p><ul><li>Failed</li><li>Passed</li><li>Not run (“manual” as opposed to “non-automated”, they require human intervention)</li><li>Inconclusive</li></ul><p>Read more about how to work with test cases in Accessibility Tools <a href="https://docs.google.com/document/d/1MG0kg7X6cMLZtGq_La4JmHOLdLkhqd3M34FtHkLg8hU/edit?tab=t.0#heading=h.j3cgcjaf5yws">here</a>.</p></td></tr><tr><td>Text alt</td><td>Text alternative, descriptive text that conveys the same essential information and function as non-text content (like images, videos, or audio) for users who cannot access the original content.</td></tr><tr><td>TOC</td><td>Table of Contents</td></tr><tr><td>Transcription, Transcript</td><td><p>A complete, written version of all spoken dialogue, sound effects, music cues, and relevant non-verbal information in audio or video content. They are often provided as separate text documents for audio-only content, such as podcasts, or as an additional accessibility feature for video content.</p><p>Disambiguation: Transcriptions provide a complete, static text document, while captions are synchronized text displayed within video content.</p></td></tr><tr><td>UA</td><td>User agent, any software that retrieves, renders, and facilitates user interaction with web content, such as browsers, screen readers, or mobile applications.</td></tr><tr><td>UI</td><td>User Interface</td></tr><tr><td>VPAT</td><td>Voluntary Product Accessibility Template, a document that helps organizations assess the accessibility of their products and services. It is a standardized template used to report how well a product conforms to accessibility standards, such as Section 508 and WCAG. Essentially, it is a way for vendors to document and communicate the accessibility features of their offerings.</td></tr><tr><td>WCAG</td><td>Web Content Accessibility Guidelines represent a single shared standard for web content accessibility that meets the needs of individuals, organizations, and governments internationally. Web “content” generally refers to the information in a web page or web application, including: natural information such as text, images, and sounds code or markup that defines structure, presentation, etc.</td></tr><tr><td>White space characters</td><td><p>Invisible characters used for spacing and formatting in text that don't display visible marks on screen or paper.<br>Examples:</p><ul><li>Space</li><li>Tab</li><li>Line break</li><li>Carriage return</li></ul></td></tr></tbody></table>
